# 本地包替换和恢复

适用范围：一期本地 `.py` / `.whl` 的同文件名覆盖安装。不同文件名（例如版本写进文件名的 wheel）仍是不同包身份，不自动合并为版本序列。云端版本管理属于二期。

## 正常路径

1. 只读检查候选包元数据和包键，拒绝正在安装、加载或已有活跃引用的包。
2. 卸载旧能力，保留旧包 sidecar。对新代码重新申请审计权限；包配置和能力启停状态保留。
3. 在 `<data_dir>/orca_plugins/.install-transactions/<安装目录名>/candidate` 准备候选包，写入包含旧配置快照的 `journal.json`。
4. 把旧目录移入 `previous`，候选目录移到安装位置。此时还没有提交成功。
5. 导入、能力注册、`on_load`、配置和 sidecar 持久化全部成功，才写 `committed` 并回收备份。

运行期间持有该 profile 的 `.runtime.lock`；第二个插件宿主不能同时打开同一 profile，避免互相恢复仍在运行的事务。OS 在进程异常退出后释放锁。

## 失败和下次启动

- 导入、依赖、注册或 `on_load` 失败：卸载失败实例，恢复旧包与该包的旧配置，保留其他包的配置。界面显示激活失败；旧版本可再次运行或在下次启动加载。
- 进程在激活中退出：下一次 Manager 初始化先读取配置并恢复事务，再初始化 CPython；恢复期间不执行插件代码。
- 恢复中配置文件写入失败：保留 `rollback` 日志，不允许激活未恢复完成的候选。修复文件系统问题后重启继续恢复。
- journal 尚未发布就退出：确认没有 `previous` 后清理孤立 staging，使后续安装可以继续。
- journal 损坏、身份不匹配、符号链接、备份丢失：报错并保留现场。不要直接删除 `previous`；先另存事务目录，检查日志和磁盘权限后恢复。
- 已提交但备份删除失败：保持成功决定，下次启动只重试清理，不降级到旧包。
- 卸载尚未激活的候选：先恢复事务再卸载，避免下次启动把已删除的插件重新恢复出来。

## 共享依赖与 wheel 缓存

共享依赖发布使用 `<data_dir>/python/packages/cp312`，旧目录暂存为同级 `.cp312.previous`。
启动时先持有进程内安装互斥锁和 OS 依赖安装锁，完成以下恢复，再初始化 CPython、创建或暴露共享包目录；恢复不执行插件代码：

- 有旧目录且目标缺失：把旧目录恢复为 `cp312`。
- 有旧目录且目标为空：视为旧宿主在恢复前创建的空目录，移除空目录并恢复旧依赖。
- 有旧目录且目标是非空目录：保留已发布的新目录，只清理旧备份。
- 目标被普通文件阻塞、目标/备份是符号链接或备份不是目录：拒绝初始化并保留旧备份；修复文件系统问题后重启重试，不以新建空目录绕过错误。

macOS 的真实 uv 安装、生产重命名完成后强制退出及独立进程恢复已通过九步回归，覆盖中断发布、
旧空目录、阻塞后重试和已完成发布。最终生产证据为 ON37 的 `release_2.4.1/host-ci-native-11/dependency-recovery-中文/results.json`；
此前私有候选和真实故障基线证据独立保留。故障注入仅用于播种测试进程，
恢复进程不注入，故障库不进入发行包；Windows/Linux 不运行该 macOS 注入测试，不能记为通过。

主 wheel 和附带依赖 wheel 的解压缓存另走完整性检查与事务发布：失败解压不发布部分目录，
缓存缺失/损坏或归档变化时重新验证并恢复；已有完整目录不能被失败替换破坏。真实 Manager 导入、
Script 回调及跨进程缓存复用已通过十二项 macOS ON37 生产回归（`host-ci-native-11/wheel-cache-recovery-中文/results.json`）。具体 wheel 场景、哈希记录、
正式目标和执行入口见 [HOST_CI.md](HOST_CI.md)，不把脚本合同当作 Windows/Linux 原生验收。

## 边界

这里用原子重命名处理进程崩溃；没有承诺 `fsync` 等级的断电耐久性。恢复不撤销插件写入外部文件、网络请求等副作用，也不删除共享依赖目录里新增的包。依赖安装另外用 staging 和已有版本约束防止覆盖旧依赖。

卸载与退出生命周期已接入统一协议；九个原生生产场景已通过，覆盖单项/批量卸载与重载隔离、
shutdown 等待、replacement/delete 忙时拒绝与完成后重试、同线程重入、析构后的完整清理及持 GIL 的 shutdown。
证据为 `release_2.4.1/lifecycle-production-01/results.json`，后续完整门禁也包含这九项，见 [HOST_CI.md](HOST_CI.md)。
这些原生结果不代替 Pages、Dock、纹理与实际切片消费者的 GUI 验收；各项证据范围保持独立。
Windows/Linux 原生、三端文件系统错误组合和发行包测试仍待验，不据此勾选 L32 全量验收。

自动化合同及真实桌面流程证据见 [VERIFICATION.md](VERIFICATION.md)。
